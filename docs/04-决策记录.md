## 开发中新增

| # | 议题 | 决策 | 来源 |

| D-31 | 私域用户报名本公司岗位后，面试未通过或被后台取消报名 | **回到报名前的归属**：报名前是本公司私域 → 回到「私域待匹配」，归属不变，重开 24h 窗口；报名前是公域 → 回公域。爽约、24h 超时、确权超时仍一律释放到公域。理由：文档的核心是保护劳务公司 300–800 元的获客投入，一次面试没过就让用户流失到公域，违背这个初衷 | Sprint 0 实现状态机时发现（spec 原写法为一律清空归属） |

| D-33 | 劳务公司怎么入驻 | 公司后台用手机号 + 短信验证码登录；手机号不是任何公司的成员时，发一张 30 分钟有效的入驻票据，凭票据上传营业执照 / 许可证并提交申请，提交人即成为该公司的老板。审核通过前可以登录，但只能看入驻进度、修改资料重新提交；驳回后状态为「入驻驳回」（新增 `REJECTED`）。入驻日 = 平台审核通过当天，免费期从这天起算 | Sprint 1 实现（文档只写了「入驻审核」，没写申请入口） |
| D-34 | 编辑招聘中的岗位要不要重新审核 | 改岗位信息（薪资、职责、食宿等）一律重新进入平台审核，审核期间不参与匹配，前端保存前提示；**只调名额不需要审核**，但新名额不能少于已被报名占用的数量。被驳回 / 下架 / 强制下架的岗位改完后可以重新提交 | Sprint 1 实现 |
| D-35 | 公司码在什么情况下失效 | 公司处于审核中、驳回、封禁、注销、倒闭时，它的所有渠道码都视为无效：扫码直接进首页，注册按自主注册处理（`source = PLATFORM`，公域）。限流状态的公司码仍有效 | Sprint 1 实现 |
| D-36 | 一个手机号能不能同时是多家公司的成员 | 不能。成员手机号全平台唯一（与求职者账号是两套账号域，互不影响：同一个手机号可以既是 A 公司驻场，又是求职者） | 02-架构 §11.3 账号域隔离 |
| D-37 | 平台运营账号的安全要求 | 用户名 + 密码 + 图形验证码；连续错 5 次锁 15 分钟；首次登录和被重置密码后必须改密；改密 / 停用 / 改角色立即吊销该账号所有会话；至少保留一个启用的超级管理员。首个超级管理员 `admin` 在空库首次启动时自动创建，密码取 `SHITU_OPS_INIT_PASSWORD` | Sprint 1 实现 |
| D-38 | 公域用户匹配度不足怎么办 | 文档只规定了「转人才经纪人」，但经纪人是劳务公司内部角色，公域用户不属于任何公司。**公域**：不建工单，提示调整条件重新匹配，会话记为 NO_MATCH 供平台看漏斗；**私域**：自动建本公司流转工单（2h 联系 / 24h 出结果，D-10），通知全部经纪人 | Sprint 2 实现 |
| D-39 | 结果「固定 3 个」与「≥80% 才展示」冲突时 | 取排序前 3，只展示其中匹配度 ≥ 80% 的（可能少于 3 个）；一个都不达标按 D-38 处理。未展示的也写入快照，供经纪人和调参参考 | 核验 R-02 |
| D-40 | 实名 V1.0 的实现顺序 | 上线版按 D-15：OCR → 二要素 → 再手输比对。开发期没有真实 OCR / 二要素服务，先走「姓名 + 身份证两次输入 + 二要素（Mock）」，出生日期从号码解析；接入阿里云时补 OCR 一步，接口不变 | Sprint 2 实现，待第三方资质 |
